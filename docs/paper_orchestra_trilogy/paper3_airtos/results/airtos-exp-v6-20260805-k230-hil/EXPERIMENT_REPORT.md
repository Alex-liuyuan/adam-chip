# AIRTOS 第六版实体开发板实验报告

## 1. 结论先行

截至 2026-08-05，四个核心实验中的全部短周期实体板实验和二十四分钟持续运行正式轮次均已完成，并由机器审计器复算通过。二十四分钟轮次只形成短时连续稳定性证据，二十四小时长测留作后续补充。

本轮最重要的正面结果是：联合准入、调度重放、内存租约、真实物理数据搬运、迟到事件隔离和恢复门控均在预注册规模内达到零容忍端点。最重要的反面结果是：原计划中的 4 微秒向量最坏执行时间和 10 微秒中央处理器最坏执行时间没有覆盖板上观测到的最大值，因此当前计划不能用于声称 K230 上的硬实时期限安全；控制操作也没有达到“低于最短执行段 5%”的严格低开销阈值。

这不是一次冒烟测试，也没有使用替身、模拟提供器或伪造硬件数据。真实开发板承担了程序执行、物理地址分配、缓存写回、缓存失效、直接存储器访问搬运、设备重开和温度读取。软件注入仍只被解释为板上状态机验证，不被写成真实驱动迟到中断。

## 3. 核心实验一：证据边界联合准入和原子提交

### 3.1 目的

验证计划的证据、输入域、提供器、内存和时限任一不满足时，系统都在产生执行副作用之前拒绝；验证多个线程同时竞争最后一块内存时，不出现重叠占用、半提交或拒绝后泄漏。

### 3.2 实验数据与步骤

1. 13 类准入条件各执行 300 次，共 3,900 例，其中 12 类为不安全条件，1 类为合法对照。
2. 12 类缺陷各自以及 66 类两两组合各执行 300 次，共 23,400 例。
3. 提供器在准入检查期间改变健康状态，执行 300 次。
4. 旧信任根、双信任根、新信任根和过期根组合共执行 1,500 次。
5. 2、4、8、16 个线程分别执行 100,000 次提交，总计 400,000 次。

### 3.3 结果

| 指标 | 结果 |
|---|---:|
| 单类准入案例 | 3,900 |
| 单类准入失败 | 0 |
| 联合诊断案例 | 23,400 |
| 假阳性 / 假阴性 | 0 / 0 |
| 诊断宏平均调和分数 | 1.000000 |
| 健康竞争失败 / 回滚泄漏 | 0 / 0 |
| 信任根轮换失败 | 0 |
| 并发提交操作 | 400,000 |
| 活动内存重叠 / 半提交 | 0 / 0 |

并发提交中 112,091 次被接纳，287,909 次因竞争被拒绝。拒绝率上升是资源竞争的预期行为，不是安全失败；关键端点是被接纳的区域不重叠，拒绝后没有残留。

### 3.4 支撑结论

在冻结的计划、缺陷集合和 2 至 16 线程范围内，证据边界联合准入会关闭失败路径，提交事务不产生跨会话污染。它不能证明未测试字段组合永远安全，也不能替代生产中断处理程序并发验证。

## 4. 核心实验二：调度一致性、真实算子时序和控制开销

### 4.1 目的

验证计划加载和多资源最早期限优先调度与独立参考结果一致；在实体板上测量项目编译器真实生成的中央处理器与向量算子，而不是继续使用固定成本表；测量安全控制路径是否满足预注册开销阈值。

### 4.2 实验数据与步骤

1. 实体板流式读取 49,085,520 字节语料，重放 7,950 个加载案例和 24,548 个调度场景。
2. 中央处理器加法加整流算子执行 30 批，每批 1,000 次，共 30,000 次。
3. RISC-V 向量加法加整流算子执行相同规模，共 30,000 次。
4. 时钟读取、计划加载、调度仿真、队列进出、内存租约、跟踪写入和完成中断处理共 7 类操作，各执行 30 批，每批 1,000 次。

### 4.3 结果

| 指标 | 结果 |
|---|---:|
| 加载案例 / 差异 | 7,950 / 0 |
| 调度场景 / 差异 | 24,548 / 0 |
| 中央处理器算子案例 / 数值失败 | 30,000 / 0 |
| 向量算子案例 / 数值失败 | 30,000 / 0 |
| 中央处理器最差批次第 99 百分位 | 1.592 微秒 |
| 中央处理器最大观测值 | 19.926 微秒 |
| 向量最差批次第 99 百分位 | 1.592 微秒 |
| 向量最大观测值 | 19.778 微秒 |
| 7 类控制操作最差批次第 99 百分位 | 3.741 微秒 |
| 计划期限 5% 阈值 | 5 微秒 |

计划给向量主路径登记 4 微秒最坏执行时间，给中央处理器回退路径登记 10 微秒。两个登记值都小于本轮最大观测值，因此最坏执行时间合同不适用于当前板级环境。第 99 百分位控制开销低于 5 微秒准入阈值，但队列、跟踪和完成处理的最差第 99 百分位大于 4 微秒执行段的 5%，严格低开销假设不成立。

### 4.4 支撑结论

可以写：在实体 K230 上，加载与调度实现对冻结语料和参考结果完全一致，生成算子数值正确。

不能写：当前计划已经证明 K230 上硬实时期限安全，或安全机制开销低于最短执行段的 5%。下一步必须用板上最大值、温度和竞争条件重新标定成本，生成新计划后重新走完整准入和调度实验，不能事后只修改论文数字。

## 5. 核心实验三：内存租约和真实缓存一致性

### 5.1 目的

验证多线程内存生命周期不会交叉；验证“处理器写入、写回缓存、物理搬运、丢弃旧缓存、处理器读取”完整路径在真实设备上保持数据一致，并用遗漏操作的负对照证明检测链有灵敏度。

### 5.2 实验数据与步骤

1. 2、4、8、16 线程各执行 250,000 次内存分配尝试，总计一百万次。

3. 真实物理搬运按 64、256、4,096、65,536 字节四档各执行 250,000 次，总计一百万次。
4. 每档另执行 100 次遗漏写回和 100 次遗漏失效负对照。
5. 每次完整路径都逐字节比较源和目的区域。

### 5.4 支撑结论

本轮首次为“计划驱动缓存所有权”提供真实物理证据：错误路径稳定产生旧数据，完整路径一百万次零差分。因此可在 CanMV-K230-LP4 V3.0、当前镜像、当前内存区域和四种大小范围内声称缓存动作是必要且有效的。不能外推到未测试的外设、非对齐范围或其他芯片。
